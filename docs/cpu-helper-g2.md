# G2 — nxrecomp CPU-helper execution test

**State:** source + CI submitted; compile and physical Switch Lite run pending.

This is **not** Pokémon Pokopia game code, nor actual C++ output generated by the AArch64 lifter. It is a small **manually authored synthetic function in the lifted-code style** using the genuine upstream `Ctx`, `adds64`, `adds32`, `rd32`, `rd64`, `wr32`, `wr64` and `cond` helpers.

## Purpose

Test on the original Switch's real ARM64 CPU whether a small C function manipulating `Ctx` can perform basic semantics similar to the output of an AArch64 static recompiler.

Tests:
1. Register addition then 64-bit guest-pointer store/load.
2. AArch64 integer addition flags.
3. 64-bit wraparound/carry/zero flags.
4. Conditional EQ and NE behavior.
5. 32-bit signed addition overflow.
6. Subtraction implemented using `adds64(a, ~b, 1)`.
7. 32-bit write/read helpers.

All 7 must show **PASS** on console. These tests only use a pointer into a small, real process-local buffer; there is **no guest virtual address space mapping** yet.

## Reproduce

- [Run GitHub Actions: Build nxrecomp CPU helper probe](../.github/workflows/cpu-helper-probe.yml).
- Download the artifact `pokopia-nx-cpu-helper-probe`.
- Extract the `pokopia-nx.nro` and launch it via Homebrew Menu on Switch Lite.
- The console should report `7/7 tests passed` and `ALL PASS`.
- Upload the exact build log if compilation fails and a photograph if the hardware result differs.

### Limitations

Passing G2 is **not** proof that Pokopia, the NVN2 graphics engine, the full Recompia runtime or the game's generated code will work on Switch 1. It does not benchmark game performance, frame rate or total memory use. The CPU helper implementations may evolve upstream; the test currently retrieves Recompia main during CI, so the upstream revision should be pinned for reproducible long-term measurements.
